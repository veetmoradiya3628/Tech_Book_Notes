
- As a data engineer, the core of your role is to build reliable pathways for data to move from raw sources to valuable insights. 
- batch data pipeline: These pipelines are the backbone of enterprise data strategy, responsible for processing large, finite datasets that are critical for everything from daily financial reconciliation to strategic business analytics.

- batch data pipelines
	- A batch data pipeline is a sequence of processes on one or more sets of data, designed to ingest, transform, and sink that data, in large, discrete chunks, or "batches", at scheduled intervals.
	- use cases
		- Periodic reporting
		- Large scale transformations
		- Data warehousing
		- Data migration
		- Scheduled backups
- components and stages
	- Data sources
		- Origin of your raw data, which can come in various formats (CSV, JSON, database tables, log files etc)
	- Data Ingestion
		- from source to 'landing zone' or 'staging area'
	- Data Transformation
		- Ingested data may be cleaned, validated, enriched, mapped, and/or restructured into a consistent and standardized format, before landing in the destination sink.
	- Data Sink
		- Final store
	- Downstream Uses
	- Orchestrate and Monitor

- Batch processing vs. batch pipelines
	- Batch data processing
		- The method or technique of handling data. It's about collecting data over a period (a "batch") and then processing that entire batch in a single, scheduled run.
	- Batch data pipelines
		- The entire automated system or infrastructure that implements batch data processing. It's the series of interconnected stages that systematically move and process data in batches from source to destination.
- Key features of batch data processing
	- Scheduled and automated
		- periodic execution jobs should have scheduled and automated nature
	- High throughput
		- rapid processing of large quantity of data records.
	- Latency
		- latency is allowed as this is "offline" behavior
	- Resource optimization
		- "burst" resource consumption
- pipeline challenges
	- Volume and scale
	- Data quality
	- Complexity and maintainability
	- Reliability, error handling, and observability

- Data connections and orchestration
- I/O and connectors
	- At its core every data pipeline performs I/O (Input/Output) operations
- Connectors
	- Connectors are pre-built software components that acts as translators or adapters. They contain all the necessary logic to handle the communication, authentication, and data formatting required to read from a specific source or write to a specific sink.
- Target data sink depends on the Usecase and what we wanted to do with generated output data
- CloudSQL
	- Cloud SQL is an excellent sink for a batch pipeline when
		- The final data needs to be served to applications that require a traditional, relational database (like MySQL, PostgreSQL or SQL Server)
		- The JDBC IO connector is typically used for this process, whether you are using Dataflow or Serverless for Apache Spark connectors.
- BigQuery
	- BigQuery is Google's serverless, petabyte-scale data warehouse and is the recommended sink for most batch pipelines.
	- Optimized for bulk inserts
	- Massive scalability
	- Cost-effective
- Cloud Storage
	- Cloud storage is the most common and versatile destination for the raw or intermediate output of a data pipeline
	- Highly scalable and durable
	- Flexible formats
	- Staging areas
- Few best practices
	- Optimized formats
	- Native connectors with batch write
	- Batching and buffering
	- Schema consistency/validation
	- Error handling
	- Monitoring I/O performance

- Orchestration
	- Orchestration can automatically make sure all your data processing tasks - ingesting data, transforming it, and sinking it - run in the correct order, at the correct time. This process involves defining a clear workflow where you can set the sequence of operations and establish dependencies between them
	- DAG
		- Directed Acyclic Graph
	- Cloud Composer
		- It manages execution
		- It automatically tries again if something goes wrong
		- It keeps a close eye on DAG and worker node progress
		- built on Apache airflow
		- DAGs are the blueprint for your data pipelines, providing a clear, visual way to represent and manage the flow of data and the dependencies between tasks
- The principle remains the same
	- Build and validate your data processing logic first
	- Then use Cloud Composer to turn that manual step into reliable, automated production pipeline.
