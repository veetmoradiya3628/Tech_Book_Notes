- BigQuery : The analytical engine
- BigQuery is a serverless, highly scalable, and cost effective analytical data platform that can query petabytes of prepared streaming data in a matter of seconds. Because SQL is a SQL columnar storage system, it's optimized for analytical queries making it perfect for answering business-critical questions.
- Batch vs. streaming ingestion
- ETL vs. ELT
- BigQuery Storage Write API
	- ideal for real-time ingestion
- BigQuery Data Transfer Service (DTS)
	- DTS is a fully managed, automated data loading service for scheduled transfers which is incredibly useful for pull data from other Google applications like Ads and YouTube, or from cloud storage services like Amazon S3 on a recurring schedule.
	- DTS is a set it and forget it 
- Change Data Capture (CDC)
	- BigQuery CDC a design pattern that streams changes from source databases directly into BigQuery.
	- CDC collects and synchronizes updates made to source data systems (like databases & file systems) with BigQuery to analyze and detect application changes in real-time.
- Complex transformations: Dataflow and Continuous queries

- Reverse ETL
	- Reverse ETL is the process of moving data from a storage system, like BigQuery back into operational systems. This allows you to activate your data by making it available in the tools your business teams use every day like CRMs, marketing automation platforms, and advertising networks.

- Bigtable
	- Google Cloud's fully managed, petabyte-scale NoSQL database service
	- Useful for applications looking for real-time operations data in sub millisecond latency
	- Uses **Colossus**

| Features               | Bigtable                                                                                              | Bigquery                                                                                         |
| ---------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Data structure         | Unstructured, Optimized for NoSQL queries. its key-value and wide-column database                     | Structured, optimized for SQL queries but supports flexible semi-structured data formats.        |
| Deployment scope       | Global.                                                                                               | Regional                                                                                         |
| Latency and Throughput | Milliseconds for NoSQL queries over large datasets.                                                   | Seconds for interactive SQL queries over large datasets (petabytes).                             |
| Primary Use cases      | Real-time application serving, IoT and time series data, Machine learning workloads, Data Integration | Real-time analytics, Data warehousing + business intelligence, ML workloads, Geospatial analysis |

- Schema design: Speed through simplicity
	- Bigtable's low-latency, high-throughput linear scalability is a direct result of its architecture. It prioritizes massive scale over strict ACID semantics, using a simple data model to optimize performance. Throughput, measured in Queries Per Second (QPS), scales proportionally with the number of nodes, making it ideal for internet-scale workloads with unpredictable traffic spikes.
	- Low latency
	- High throughput linear scalability
- raw key is important concept
- common use cases
	- Real-time application serving
	- IoT and time-series data
	- Machine Learning
	- Adtech and retail
- Bigtable is ideal solution for applications that require fast, real-time data access and can grow with your business needs.
