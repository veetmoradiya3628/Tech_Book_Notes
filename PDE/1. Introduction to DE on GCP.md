- Data lake vs. data warehouse

|                   | Data lake                                                                           | Data warehouse                                          |
| ----------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------- |
| Data format       | Native (unstructured, semi-structured, structured)                                  | Schema (structured or semi-structured)                  |
| Data types        | Raw                                                                                 | Pre-processed and aggregated from multiple data sources |
| Purpose           | Data science, applications, business, decisions                                     | Long-term business analytics                            |
| Dependencies      | Tools/processes to enable data discovery, governance, security, metadata management | Standalone                                              |
| Service           | Cloud storage                                                                       | BigQuery                                                |
| Query performance | Moderate                                                                            | Very Fast                                               |
| Cost              | Low                                                                                 | Higher                                                  |
- Data lake is schema on read
- Data warehouse is schema on write

- ELT / ETL Architecture
- ELT
	- Extract, Load, transform
	- Use an ELT pipeline to apply transformations after data is staged in Big Query
	- Big Query supports procedural language queries to perform multiple statements in a sequence
	- User-defined functions (UDFs) transform data by using SQL or JS
	- Stored procedures - Collection of SQL statements
	- Remote functions provide transformations with more complex programming logic
	- Jupyter notebooks for data exploration and transformation
	- Query scheduling
- Dataform (ELT)
	- Dataform is a serverless framework to develop and operationalize ELT pipelines in SQL
	- Unifies data transformation, assertion and automation in Big Query
	- SQL workflow development and compilation run in Data form, workflow executions runs in Big Query
	- `sqlx` definitions
	- Dependencies - implicit / explicit 
	- Data form compiles your definitions into SQL scripts and chains them into a workflow
	- The compiled graph visualizes the SQL workflow with its definitions and dependencies
	- Scheduling can be configured
		- Internal
		- External - Cloud Scheduler, Cloud Composer
	- Provides benefits such as 
		- Git Integration
		- Code review
		- Testing
		- Reusable SQL
		- Documentation
		- Dependency management
		- SQL version control
	- Incremental tables - only process diff data
- ETL
	- Extract, transform, load
	- ETL services by GCP
		- Dataprep
		- Cloud Data Fusion
		- Dataproc
		- Dataflow
	- Dataprep by Trifacta is a serverless, no-code solution to build data transformation flows
	- Preview your transformations and gives recommendations for your workflow
	- Cloud Data Fusion is a GUI based enterprise data integration service
	- Batch data processing
		- Dataproc allows running Hadoop and Spark workloads
		- Dataproc is Managed service for data processing using Hadoop and Spark
		- Dataproc cluster can use HDFS on persistent disk or GCS
		- Manage and execute workflows with Dataproc workflow templates
		- Apache Spark is a popular framework for many data processing tasks
		- Dataproc serverless for spark allows spark workloads without cluster management
	- Stream data processing
		- Near real-time analytics
		- Pub/Sub to ingest high volumes of event data and distribute to different consuming systems
		- Dataflow can process both batch and streaming data using Apache beam programming model
		- Dataflow template for recurring pipeline executions
	- Use Bigtable as a sink in your streaming data pipeline for millisecond latency analytics

		- CronJob in the cloud

		- Develop your DAG in python using Apache Airflow operators and submit it to cloud composer for execution
		- Workflow orchestration
	- Cloud Run 
		- Cloud Run functions to execute code based on Google cloud events
	- Eventarc
		- Event router
	- Build a unified event-driven architecture for loosely coupled services with Eventarc
